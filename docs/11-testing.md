# 11. Testing

The project is covered by three layers of automated tests: unit, functional, and integration. The goal is not exhaustive coverage but enough verification to catch regressions in the parts most likely to break: data loading, the inference pipeline, and the public API.

## 11.1 Strategy summary

| Layer | What it verifies | Tooling | Location |
|---|---|---|---|
| Unit | Pure functions: dataset row parsing, image preprocessing, label encoding, care-card serialization | pytest | `tests/unit/` |
| Functional | The classifier produces sensible output on a tiny fixture image | pytest + a pinned 1-MB fixture | `tests/functional/` |
| Integration | The Flask API behaves correctly end-to-end against a test database | pytest + pytest-flask + SQLite in-memory | `tests/integration/` |

Target coverage: **≥ 70% of backend code**, measured by `pytest-cov`. Coverage report is generated by `pytest --cov=backend --cov-report=term --cov-report=html`.

## 11.2 Unit tests

### `tests/unit/test_split_data.py`

- The 70/15/15 split sums to the input length.
- The split is stratified: every class is present in every subset.
- The seed is deterministic: rerunning the split yields identical manifests.

### `tests/unit/test_preprocessing.py`

- A 1024×768 JPEG is correctly resized to 224×224.
- Normalization uses ImageNet mean and std.
- A 16×16 image raises a `ValueError` (too small).
- A corrupted file raises `PIL.UnidentifiedImageError`.

### `tests/unit/test_models.py`

- `PlantClassifier.predict_topk(image, k=3)` returns three results sorted by descending confidence.
- Probabilities sum to approximately 1.0.

## 11.3 Functional tests

### `tests/functional/test_inference.py`

A small fixture set of three images (one clear Pothos, one clear Aloe, one ambiguous Snake Plant) lives in `tests/fixtures/`. The test:

- Loads the deployed checkpoint.
- Asserts the top-1 species for the clear Pothos is Pothos.
- Asserts the top-1 species for the clear Aloe is Aloe.
- Asserts the ambiguous case yields `low_confidence: true`.

### `tests/functional/test_care_lookup.py`

- For every one of the 47 species, the database contains exactly one care profile.
- For every species, there are exactly two toxicity records (cat, dog).

## 11.4 Integration tests

Run with an in-memory SQLite database and a stub classifier that returns canned predictions.

### `tests/integration/test_api_health.py`

- `GET /api/health` returns 200 with model name and 47 classes.

### `tests/integration/test_api_predict.py`

- `POST /api/predict` with a valid 224×224 JPEG returns 200, three results, sane shape.
- `POST /api/predict` with no `image` field returns 400.
- `POST /api/predict` with an 11 MB payload returns 400.
- `POST /api/predict` with a 16×16 image returns 400.
- `POST /api/predict` records one row in `predictions`.

### `tests/integration/test_api_species.py`

- `GET /api/species` returns 47 items.
- `GET /api/species?q=pothos` returns at least one item including Golden Pothos.
- `GET /api/species/17` returns the Golden Pothos full card with care and toxicity nested.
- `GET /api/species/9999` returns 404.

## 11.5 Continuous integration

A GitHub Actions workflow at `.github/workflows/ci.yml` runs on every push and pull request:

1. Set up Python 3.11.
2. Install dependencies.
3. Run `ruff check .`
4. Run `pytest --cov=backend --cov-report=xml`.
5. Upload the coverage XML as an artifact.

## 11.6 Manual testing checklist

Some checks are difficult to automate and are validated by hand before release:

- Upload a real photo from a phone camera (HEIC converted to JPEG).
- Drag and drop a photo from the desktop into the dropzone.
- Submit a photo of a dog (out-of-distribution input) and confirm the low-confidence banner appears.
- Resize the browser window from 320 px to 1920 px and confirm no layout breaks.
- Toggle the network throttling to "Slow 3G" in DevTools and confirm the loading state remains responsive.
